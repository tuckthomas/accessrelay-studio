# Recorded controller shot trainers

Studio beta.42 fixes isolated one-tap playback and preserves the Run scripts state when tuning. The recorded-input trainer introduced in beta.41 adds a generic `controllerTrainer` capability to controller packs.
Shot labels, instructions and bounded timing/tempo corrections belong to the pack;
the host provides recording, Lua conversion, controller assignment and shared controls.
The NBA 2K27 Shot Trainer 2.0.1 package is in the separate Marketplace repository.
It runs independently of installed model-training/vision implementations.

Open **Controller → Plugins**, choose the trainer and create a controller profile.
Record each shot separately, supply baseline feedback and convert it to Lua. Then
assign an available input. Practice feedback adjusts only the selected shot.
Hold and stroke durations have synchronized sliders and numeric millisecond fields.
Feedback corrections are shown before applying, applied once per click, and cleared
after saving. Corrections and assignments retain the current Run scripts state; output is never auto-started. A brief tap plays the entire shot after the assigned input is released.

Physical capture and generated Lua include only the selected shot input: both right-stick axes or the selected face button. Left-stick movement, triggers and other buttons remain live. Idle time before shot onset and after neutral release is excluded from playback. Captures must contain one complete shot-input press/release, or a down
hold and return to stick center. Intermediate down-to-up samples enable stroke/tempo
tuning. Button holds and simple stick releases have no measured stroke to adjust.
The trainer does not infer shot type or synthesize missing movement samples.

Each Lua script retains its immutable physical baseline, original feedback, current
phase durations and latest applied feedback in `training`. Profile format **7**
preserves this data across restarts/import/export. Earlier profile versions still
load. Unedited trainer scripts generated by beta.41 are automatically repaired on startup, preserving the complete original baseline, tuning durations, script ID and paddle mapping. The pre-repair profile is backed up by the existing profile migration workflow. Custom Lua edits are not rewritten. Older Studio builds cannot load format 7. Lua exports contain the current
playable replay; export the controller profile to retain trainer metadata as well.
Custom Lua source edits are retained and make trainer tuning unavailable until the
user records a replacement. Re-recording preserves the previous script and assignment
until conversion succeeds. Occupied controller mappings are never silently replaced.

`trainerStart`, `trainerConvert`, `trainerAssign` and `trainerTune` are controller
bridge commands. All require a matching pack/version/hash and the editable controller
profile. Recording ownership binds the selected profile, pack, shot and shot input;
ordinary recorder commands cannot be converted as an unrelated trainer baseline.
Starting a capture pauses scripts and uses the native physical-input recorder.
Conversion requires the capture to stop with no interruption note, validates the
feedback, compiles the Lua, saves it and only then discards pending input. Saving tuning cancels any in-progress old replay and leaves the script session switch as it was.

Retiming edits intervals from the original capture, preserving raw values, sample
order and the lengths of other phases. Later timestamps shift. Every interval keeps
at least one millisecond per sample, each editable duration is at most 10000 ms and
the whole replay is at most 15000 ms. Invalid edits leave saved Lua untouched.

Verification:

```powershell
pnpm --dir src/AccessRelayStudio/DesktopUi test
dotnet run --project src/AccessRelayStudio/Verification/Verification.csproj -c Release -- --controller-trainer
dotnet run --project tools/packs/PackTool.csproj -c Release -- ../AccessRelayMarketplace-Source/packages/nba2k27/2.0.1/pack.json
```

The portable checks compare actual Lua playback at every millisecond with retimed
recordings, including movement, button release, shot independence and persistence.
For native UI verification only, `--controller-trainer-fixture <isolated-root>
<manifest-path>` creates labeled synthetic profiles and imports the checked pack
inside that root. Launch the desktop with `--ui-verification-data <isolated-root>`.
Synthetic captures do not establish hardware latency or in-game timing quality.

The engine advances an existing Lua replay before evaluating a new press on its completion tick. Fresh raw paddle edges after a settings apply are retained; held controls after disconnect still require release. Verification includes zero-held-level paddle taps, consecutive completion-tick presses and actual StudioRuntime tuning with simulated devices.
