# AccessRelay virtual microphone host

`AccessRelay.VirtualMicHost.exe` exposes a capture-only USB Audio Class 2 microphone using the loopback USB/IP protocol and Windows' USB audio class driver. It is a local helper for AccessRelay Studio. The app supplies 48 kHz mono IEEE float PCM over stdin and receives `READY` on stdout after attachment. USB capture requests pace the jitter buffer. `ACCESSRELAY_MIC_PRIME_MS` sets its initial and recovery buffer in milliseconds and defaults to 60. The queue holds up to 320 ms beyond that target, capped at 900 ms. When capture starts after a long idle period, the host keeps only recent audio near the target. Closing stdin detaches the device. The host reports buffer underruns, discarded samples and largest capture request on stderr when the input closes.

The helper uses [`usbip-audio`](https://github.com/network-audio/usbip-audio/tree/58032ab0664ffec1d0c178f40a3a69359c21f597) at pinned revision `58032ab0664ffec1d0c178f40a3a69359c21f597` under MIT. [`windows-rs`](https://github.com/microsoft/windows-rs) licenses for its transitive Windows dependencies (`windows-sys` 0.59.0, `windows-targets` 0.52.6, `windows_x86_64_msvc` 0.52.6) accompany the binary. The separately bundled `usbip-win2` host controller driver and client retain their upstream licenses.

The helper requires `AccessRelay.VirtualMicUsbId.txt` beside the executable. The repository build script generates it for an authorized VID/PID. The shared [pid.codes test VID/PID](https://pid.codes/1209/0001/) is available only in explicitly marked private test builds. See `docs/virtual-devices.md` in the source repository for build and distribution instructions.
